# FG-141 — authoritative cycle IPC and service

## 1. Summary

Added IPC protocol version 2 messages for prepared-session review and
activation, expanded status with cycle phase information, and implemented the
flow in `InMemoryFocusService`. Preparation compiles the plan without applying
policy, expires after two minutes, and is consumed once. The service derives
phase status from UTC and accepts idempotent normal-mode break skips; strict
mode rejects them.

## 5. UX implications

The next Desktop slice can render an exact service-generated phase review, a
partial/current phase, the next transition, and an updated end time after a
normal skip. No phase advancement is performed in Desktop code.

## 6. Security implications

Preparation applies no policy and has a finite two-minute lifetime. New cycle
payloads reject unknown JSON fields, including nested fields, and normal skip
is bound to the service's current phase. The protocol version and development
pipe name moved to v2, so old clients are rejected rather than interpreted
partially.

## 7. Limitations

This slice uses the in-memory service plan. It does not yet sign the complete
cycle policy, authorize independent application/browser break leases, persist
cycle plans, or reconstruct them after reboot. Those are FG-142 requirements.
