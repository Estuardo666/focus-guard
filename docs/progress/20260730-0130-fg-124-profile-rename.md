# FG-124 Profile Rename

## 1. Summary

Added persistent profile rename to the Profiles screen. Names are trimmed,
validated, checked against existing profiles, and saved using the existing
profile ID so rules and metadata remain attached to the same profile.

## 6. UX implications

The Profiles screen now includes a localized profile-name field and Rename
button. The button activates only for a valid, changed, non-duplicate name.
Validation explains empty, overlong, and duplicate names. After success, the
same profile remains selected under its normalized new name.

## 7. Security implications

Rename is unavailable while a session is active or the view model is busy.
Active immutable policy snapshots are unchanged. No rule IDs, enforcement
settings, service state, or recovery state are modified.

## 8. Limitations

- Compiled XAML and automated tests validate the UI contract; no screenshot
