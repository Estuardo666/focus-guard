# FG-131 plan — recover the process agent when Desktop opens

## Acceptance criteria

1. Opening the installed Desktop starts its sibling `FocusGuard.ProcessAgent.exe`
   when no instance from that exact path is running.
2. Desktop does not start a duplicate agent.
3. Missing or invalid companion paths fail safely without preventing Desktop from
   opening.
4. Desktop remains configuration/status only; application enforcement stays in
   `FocusGuard.ProcessAgent`.
5. Automated tests cover missing, already-running, and start-required outcomes.

## Implementation plan

1. Add a small Desktop startup coordinator with injected process discovery and
   launch boundaries.
2. Call it only after the Windows Desktop single-instance gate succeeds.
3. Add lifecycle regression tests and run format, build, and relevant tests.
4. Update `TASKS.md`, record a completion checkpoint, and refresh graphify.

## Implications

- Security: only the fixed executable beside the running Desktop is eligible;
  no user-provided command or arguments are accepted.
- UX: reopening FocusGuard repairs application-channel health without a reboot
  or manual process launch.
- Recovery: launch failure remains fail-open and visible as degraded health; it
  never blocks Desktop startup or changes the service-authoritative expiration.
