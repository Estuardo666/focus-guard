# FG-173 — Phase 4: authenticated owner/role IPC

Full milestone remains IN_PROGRESS, not completed by a policy test alone. Requirements: explicit consenting owner (not elevated installer identity), trusted binary roles, native SID/logon/PID identity, protected canonical image/hash and manifest, owner-only pipe rights without create-instance, remote rejection/first-instance protection, client server verification against SCM, bounded/cancelable endpoints, real unauthorized and legitimate compatibility proof.

Initial implementation: separate reusable Ipc.Windows library with typed role/operation policy and native metadata primitives. Tests must exercise actual GUID pipe PID/SID capture and actual readonly SCM status/config. It is not yet referenced by shipped components; production enforcement must follow explicitly, rather than marking a green foundation as Phase 4 completion.

Roles: Desktop and future explicitly provisioned Host own control requests only; Agent owns heartbeat/ack/audit only; NativeMessaging owns extension health/policy/audit/capture only; explicitly provisioned Diagnostic follows owner control for legacy drills. Recovery stays elevated and offline, absent from the pipe role list. Deny unknown messages, other owners/logons, wrong roles, Temp copies, altered hashes, writable/reparse image roots and non-SCM servers. SID/PID/path sent in payload is never identity.

Architecture constraint: LocalService could not query interactive processes in FG-112. An actual native probe also proves Impersonation available before first message; keep Identification. A security-reviewed candidate is a narrowly scoped PROCESS_QUERY_LIMITED_INFORMATION grant on each explicitly consenting trusted client process to LocalService (no token/memory/write/termination rights), then capture native image under service identity, keeping caller identification read-only and reverted. The owner explicitly authorized this metadata consultation in the updated goal. Current-process-only helper with exact0x1000/restoration has been implemented and exercised in the isolated test runner; no accounts or other processes changed. This is code design pending real LocalService compatibility proof, not authorization to modify live process/machine ACL during this milestone. Never change service identity or broaden accounts to bypass it.

Owner provisioning must use the original interactive Windows session or an explicit owner selection, never blindly WindowsIdentity.GetCurrent() after UAC. Protected installation policy/manifest is generated atomically with update/rollback coverage. No install/elevation or account/ACL changes executed without separate owner-present authorization required by AGENTS.
