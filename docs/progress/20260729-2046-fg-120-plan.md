# FG-120 — Calm motion and control-state isolation

## Goal

Remove the remaining white flashes and grey state containers reported in the
owner's five screenshots, then bring FocusGuard interaction motion in line
with the provided macOS/Arc/Linear/Notion direction.

## Root cause hypothesis

Confirmed from the style graph: broad application selectors such as
`Button:pointerover`, `Button:pressed`, `Button:disabled`,
`ListBoxItem:pointerover`, and `ListBoxItem:selected` still match controls that
already have dedicated `FgNavButton` and `FgPresetItem` themes. Those global
states compete with the theme-local states and expose grey/white Fluent
painting. Opening the strict modal also sets `ApplicationShell.IsEnabled` to
false, forcing every sidebar button through a disabled-state transition at
once; closing reverses it.

## Acceptance criteria

- Navigation rows have no persistent surface; hover is only 4% white, active
  state keeps a transparent surface, and only the active icon uses the accent.
- Dedicated navigation and duration themes cannot receive standard button or
  list-item hover/pressed/disabled painting.
- Standard buttons use a FocusGuard-owned template, subtle surface lift,
  stronger border, soft shadow, `scale(1.015)` hover, and `scale(0.985)` press.
- Duration presets use only their dedicated theme and never the generic grey
  list-item states.
- Modal open/close does not disable the shell; the overlay and focus cycle
  retain interaction blocking.
- Modal motion is 280 ms fade plus scale `0.97` to `1`; primary screen entry is
  260 ms fade plus 6 px lift.
- Inputs, switches, checks, buttons, selectors, and popup surfaces use
  centralized, non-linear motion values.
- The timer halo breathes on a 5.5-second cycle without unsupported
  `RenderTransform` keyframes.
- Design-contract tests fail against the old styling and pass with the fix.

## Implementation plan

1. Replace broad global button states with an implicit FocusGuard
   `ControlTheme` containing its own template and state transitions.
2. Remove broad `ListBoxItem` states and keep all duration states inside
   `FgPresetItem`.
3. Add semantic hover/shadow/motion resources and apply subtle physical scale
   to standard buttons.
4. Refine navigation icon state, screen motion, popup/tooltip motion, and modal
   fade/scale.
5. Stop toggling `ApplicationShell.IsEnabled` while preserving hit-test and
   keyboard-focus isolation.
6. Add red/green regression tests, launch the corrected Desktop, run the full
   validation suite, update graphify, and rebuild the installer.

## UX implications

Controls will interpolate from their current state without inherited Fluent
flashes. Hover feedback becomes quieter but easier to read through combined
luminance, border, shadow, and sub-pixel-scale cues. Dialog and screen motion
will feel continuous and restrained.

## Security implications

No enforcement, service, IPC, storage, strict expiration, browser policy, or
recovery semantics change. The modal continues to cover the shell, captures
pointer input, cycles keyboard navigation inside the dialog, and restores
focus after closing.

## Recovery implications

None. Recovery warnings, acknowledgements, code copy, cancellation, and exact
expiration remain visible and unchanged.
