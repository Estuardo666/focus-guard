now owns activation, status, remaining time, normal stop, periodic expiration,

end time, normal stop, strict confirmation, and an explicit warning that the
displayed profile rules remain mock and enforcement is not connected.

## UX implications

Focus no longer says “service simulator connected.” It clearly separates real
service-owned timing from unconnected application/website enforcement. Strict
mode shows the exact end time, one-time recovery code, saved-code and unsaved
work acknowledgements, and the exact required confirmation sentence.

Profiles, Schedule, Activity, and Settings remain nonfunctional navigation
placeholders and are not claimed as implemented.

## Security implications

- Control IPC is local, bounded, versioned, strictly shaped, correlated, and
  protected against network access.
- The plain recovery code never crosses IPC or persists.
- Strict activation requires a valid credential and a 1-minute–24-hour delay.
- Service and Desktop continue to state that enforcement is disconnected.
- Installed binaries grant SYSTEM/Administrators full control for servicing,
  while LocalService has read/execute only; machine state grants LocalService
  modify.

## Limitations

- The displayed profile and 12/4 rule counts are mock data.
- No application or website policy is enforced.
- Normal sessions survive Desktop restart but not service/OS restart; strict
  sessions persist through service restart.
- Strict activation/recovery was automated in tests but not armed on the
  owner's primary machine in this checkpoint.
- Visual UI automation could not capture the Avalonia window on this Windows
  environment; owner inspection remains the visual record.
