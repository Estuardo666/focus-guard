# FG-113 implementation plan

## Scope

- Show the saved application and website rules for the selected profile in the real Desktop flow.
- Allow one saved rule to be removed at a time and persist the updated profile.
- Keep the immutable policy of an active or activating session unchanged; profile editing affects only future sessions.
- Complete user-facing localization and accessibility polish for the affected flow.
- Produce reproducible Chrome and Edge extension distribution artifacts without storing publisher credentials.

## Vertical slices

1. Persistent rule lists and individual removal, including service-state editing guards and Desktop/storage tests.
2. Resource-backed strings and accessible labels for the profile rule experience.
3. Deterministic Chrome/Edge package generation, validation, documentation, and rollback checks.

## Security, UX, and recovery

- Removing a profile rule never mutates an already acknowledged enforcement policy.
- Editing is disabled while the service reports `Activating` or `Active`, avoiding misleading partial changes.
- URL query parameters remain rejected and are never displayed or logged.
- Protected-process exclusions and fail-open enforcement remain service-owned and are not configurable here.
- Distribution packages contain no keys, secrets, browser history, or machine-specific state.
- Rollback consists of restoring the previous profile row or removing generated artifacts; installed service recovery remains unchanged.

## Acceptance evidence

- Tests cover deleting one application rule, deleting one website rule, persistence, selection preservation, and active-session guards.
- Formatting, .NET build/tests, extension tests, package validation, and manual Desktop verification pass.
- `TASKS.md`, checkpoint documentation, and the graphify graph are updated.
