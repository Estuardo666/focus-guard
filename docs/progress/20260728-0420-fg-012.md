# FG-012 checkpoint

## Summary

Added a separate `FocusGuard.Service` project with an `IFocusService` contract and `InMemoryFocusService` implementation for safe desktop/service integration tests.

## Acceptance evidence

- Service reports ready/inactive status without a session.
- Valid activation creates an authoritative domain session and rejects a second active session.
- Expiration is evaluated from injected UTC time and permits a later activation.
- Normal sessions can stop; strict sessions cannot be stopped through the normal stop path.
- Invalid activation requests do not change service state.
- Release build completed with zero warnings/errors.
- Domain tests: 18/18; contract tests: 5/5; desktop tests: 13/13; service tests: 5/5.

## Security implications

The implementation is memory-only and uses no process, browser, pipe, Windows Service, persistence, elevation, or privileged API. It is explicitly a simulator and makes no real enforcement claim.

## UX implications

The service status model provides the authoritative state shape needed by future desktop status screens, including service and extension readiness and remaining seconds.

## Limitations and next task

No transport, persistence, process monitoring, extension heartbeat, or desktop wiring was added. Next: FG-013 SQLite schema and temporary-directory integration tests.
