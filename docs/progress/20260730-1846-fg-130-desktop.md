# FG-130 Desktop checkpoint

## Summary

Desktop now admits one instance per Windows user/session. A second launch sends
the fixed activation signal to the existing process and exits. Hidden inactive
refresh moves from one second to five seconds; visible or active refresh remains
one second, restoration refreshes immediately, and hidden timer-halo animations
are paused. Repeated status snapshots no longer invalidate the full visual tree.

## Files changed

- Desktop startup, application lifetime, main window, and focus view model
- `DesktopSingleInstance.cs`
- Desktop lifecycle and view-model tests

## Tests added

- primary/secondary instance activation
- visible, active, and hidden-inactive refresh intervals
- identical status emits no UI notifications
- active countdown emits timer-only notifications

## Commands executed and results

- Desktop Release build: passed, zero warnings/errors
- Desktop tests: 79/79 passed before the final aggregate run
- format verification: identified only line endings/import order; repository
  formatter applied successfully

## UX implications

Launching FocusGuard again restores the current window instead of creating
another tray icon. Visible timing and motion are unchanged. Hidden active
sessions retain the existing refresh cadence and notification behavior.

## Security implications

Activation uses per-session, per-user local Windows synchronization names and
supports no command other than showing the existing window.

## Recovery implications

No service, persistence, expiration, or recovery code changed. The Desktop
refreshes immediately when restored.

## Limitations

The installed legacy instances remain running until the owner updates or
restarts the installed Desktop; this checkpoint does not mutate the machine.
