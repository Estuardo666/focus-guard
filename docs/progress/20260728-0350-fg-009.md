# FG-009 checkpoint

## Summary

Added a mock website-rule profile editor backed by `WebsiteRule.Create`, with action selection, pattern normalization, privacy guidance, validation feedback, empty state, and removable draft rows.

## Acceptance evidence

- Supports block and allow actions.
- Supports the documented bare-domain, subdomain, path, and scheme-wildcard pattern forms through the domain normalization path.
- Rejects empty patterns and query-bearing rule patterns; query data is not retained in drafts.
- Rule rows expose normalized patterns and accessible remove actions.
- Release build completed with zero warnings/errors.
- Domain tests: 18/18 passed. Desktop tests: 10/10 passed.

## UX implications

The editor explains examples inline and makes the privacy boundary visible: query parameters are excluded by default and never shown in the draft list.

## Security and recovery implications

No browser, URL history, extension, persistence, or enforcement APIs are used. The editor only stores validated in-memory draft rules.
