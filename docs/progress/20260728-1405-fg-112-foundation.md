# FG-112 foundation checkpoint

## Summary

Added the first real-pipe E2E path from the Desktop client through service
activation and browser health, exact dual acknowledgement, confirmed process
policy, and expiration. Fixed a discovered split-brain failure: stale browser
health now revokes the browser acknowledgement lease and immediately withdraws
the process receiver too; reconnect requires a fresh exact acknowledgement.

Pinned the TypeScript toolchain and made `tsc --noEmit` a reproducible CI gate.
Added conservative executable SHA-256 caching. Hardened the installer to close
only the installed FocusGuard Desktop before replacement and cryptographically
verify a restored rollback tree.

## UX implications

Known extension loss no longer leaves invisible application-only enforcement.
The finite session can remain present for honest degraded status, but both
blocking channels are released until exact health/policy agreement returns.
Installer updates may close FocusGuard Desktop cooperatively and explain an
abort before any replacement if the app cannot close.

## Security implications

Browser acknowledgement is treated as a health lease. A stale lease cannot
authorize the process channel. SHA-256 caching reuses only a path whose length
and UTC write timestamp are unchanged before/after hashing. Rollback verification
compares relative paths and SHA-256 values for the complete restored tree.

## Limitations

Extension disappearance is acted on as soon as service health declares the
heartbeat stale; the existing 60-second alarm/90-second freshness window still
needs an explicit latency decision and real Chrome/Edge disconnect drill.
Activity persistence/UI, restart drills, performance budgets, and the real
Desktop-open installer failure/rollback injection remain incomplete. FG-112 is
not closed and `TASKS.md` remains in progress.
