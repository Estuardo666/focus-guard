# FG-131 — recover the process agent when Desktop opens

## Summary

FocusGuard Desktop now repairs a missing application-enforcement channel when it
opens. After the Windows single-instance gate succeeds, Desktop checks for the
exact sibling `FocusGuard.ProcessAgent.exe` and starts it only when an instance
from that path is absent.

## UX implications

Reopening FocusGuard after an update now restores application blocking without a
reboot or manual launch. A failed launch remains honestly visible as degraded
health and does not prevent the UI from opening.

## Security implications

Desktop accepts no configurable executable or arguments. It considers only the
fixed ProcessAgent filename beside its own installed binaries and does not
enforce policy itself.

## Recovery implications

The change is additive and fail-open. The service remains authoritative for
finite expiration, and existing installer/logon recovery remains intact.

## Limitations

This repairs the agent when Desktop opens; it is not a continuous watchdog while
Desktop is already running.
