# FG-114 — Independent enforcement channels, notification area, and `www` matching

## Status

`DONE`

## Summary

Implement one reviewable vertical slice so application enforcement continues when
the Chrome/Edge extension is absent, the Desktop close button hides the window in
the Windows notification area, and a bare-domain website rule also matches the
common `www` form used by Facebook and Instagram redirects.

## Relevant specifications and decisions

- `SPEC.md`: the service is authoritative; application and website enforcement
  are separate components; activation requires acknowledgement from required
  components; extension removal must surface degraded health.
- `UX_SPEC.md`: degraded enforcement must be visible and strict/recovery warnings
  must remain available.
- `THREAT_MODEL.md`: extension loss must degrade browser health without permanent
  lockout; policies remain finite and fail open on invalid channel state.
- ADR 0002: closing Desktop cannot end an active service-owned session.
- ADR 0008 currently couples process and browser leases; FG-114 will record a
  superseding decision for per-channel acknowledgement.

## Plan

1. Split process and browser connection state in `PolicyDistributionCoordinator`.
2. Make each IPC endpoint confirm and audit only its own channel; keep aggregate
   status degraded until every requested channel is healthy.
3. Activate a session once at least one requested enforcement channel has safely
   acknowledged, so application rules run without an extension.
4. Add a notification-area icon; intercept ordinary window close to hide Desktop,
   restore it from the icon, and retain an explicit localized Exit command.
5. Treat `www.example.com` as the canonical companion of a bare `example.com`
   rule, without broadening it to arbitrary subdomains; update both domain and
   extension matchers.
6. Add regression tests, then run formatting, build, relevant tests, the complete
   test suite, extension tests, and `graphify update .`.

## Acceptance criteria

- An exact process-agent acknowledgement confirms application enforcement even
  when extension readiness is false.
- Losing/restarting the extension does not revoke an already valid process lease.
- Browser enforcement still requires its own exact acknowledgement and reports
  degraded aggregate health while missing.
- Closing the main window hides it instead of disposing it; the notification-area
  icon restores it and explicit Exit remains available.
- `facebook.com` matches `www.facebook.com` and `instagram.com` matches
  `www.instagram.com`; unrelated subdomains still require `*.`.
- Automated tests, build, formatting, and graph update pass.

## Security implications

- Independence increases application-blocking availability but never lets one
  channel authorize the other; each still validates the exact immutable policy ID
  and hash and fails open when its own heartbeat expires.
- Aggregate health must remain degraded if any requested channel is unavailable,
  avoiding a false claim that website blocking works without the extension.
- Session expiration and service-owned recovery are unchanged.

## UX implications

- The close button becomes a reversible hide-to-notification-area action.
- The tray icon must have a tooltip and localized Open/Exit commands.
- Users can keep application blocking after reboot while the manually loaded
  extension is absent, with browser protection visibly degraded.

## Recovery implications

- Hiding Desktop does not affect the authoritative service or expiration.
- Explicit Exit only closes the configuration/status UI; it does not release a
  session.
- OS shutdown must remain able to close Desktop normally so reboot is not blocked.

## Checkpoint result

### 1. Summary

- Process-agent and browser-extension leases are independent. Each IPC endpoint
  authorizes only its own channel using the exact policy ID/hash.
- A valid application channel continues after browser-extension loss or absence;
  mixed policies remain visibly degraded until the browser channel reconnects.
- Ordinary Desktop close now hides the window and leaves an accessible FocusGuard
  icon in the Windows notification area. Clicking the icon or choosing the
  localized Open command restores the window. Explicit Exit and OS shutdown still
  close it normally.
- Bare domains match their canonical `www` companion in both C# and extension
  runtime matching. Arbitrary subdomains still require an explicit wildcard.
- The installer now recognizes close-to-tray behavior and stops only the Desktop
  UI process when replacing installed files; service-owned sessions are unchanged.
- ADR 0009 records the superseding channel-lease decision.

### 6. UX implications

- Closing the window no longer removes FocusGuard from the user's session; it is
  available from hidden notification icons and continues refreshing while hidden.
- Health copy now states that available channels continue independently and does
  not falsely say that every block is released when only the extension is absent.
- Open/Exit commands are localized in English and Spanish.

### 7. Security implications

- One channel cannot authorize another. Exact immutable policy acknowledgement,
  freshness, expiration, and fail-open behavior remain channel-local.
- Aggregate health is still false for a mixed policy if the browser is missing,
  so the UI does not claim website protection.
- The concurrent control-pipe ACL adds full control only for the exact process
  identity already hosting the pipe; generic authenticated users retain read/write
  access and do not receive create-instance rights.
- No service, registry entry, extension, ACL, or package was installed during this
  checkpoint.

### 8. Limitations

- The generated binaries are not installed on this machine by this checkpoint;
  the existing installation continues running its previous version until an
  owner-present update is explicitly authorized and completed.
- Chrome/Edge development extensions can still disappear after reboot. That now
  affects only website enforcement; store signing/publication remains FG-113's
  external blocker.
- Notification-area behavior is build-validated and close-policy unit tested, but
  no interactive click-through was performed in this non-mutating checkpoint.
