# FG-143 plan — FocusGuard UI/UX 2.0

## Scope and source priority

Implement the owner-provided Timer, Cycles, Focus Active, strict-review, and
Settings references in Avalonia. The attached screenshots control composition;
the 2026-08-02 Settings correction supersedes every earlier sheet/sidebar
description. Existing session, cycle, persistence, recovery, and enforcement
boundaries remain authoritative.

## Phases

1. Replace the permanent navigation rail and photographic header with one
   persistent ambient shell, a compact top command row, and a centered focus
   workspace. Keep Profiles, Schedule, and Activity reachable from a floating
   application menu.
2. Convert Settings from a routed screen to a centered, focus-trapped modal with
   fixed header, horizontal tabs, and an internally scrolling content presenter.
3. Centralize theme, component-state, spacing, and motion resources; add reduced
   motion and deterministic profile-theme/global-theme/default-theme resolution.
4. Recompose Timer, Cycles, and Focus Active around the same ring center,
   blocking cards, action zone, and global background without changing session
   authority.
5. Refine strict review to the supplied hierarchy and verify keyboard/focus
   recovery, then bring the graphical installer onto the same semantic system.
6. Run automated, static token, visual, scaling, installer, uninstall, and
   first-run checks; record evidence and remaining differences.

## Security implications

- Desktop remains presentation/configuration only; it does not advance phases,
  release policy, or activate strict mode outside the existing service protocol.
- Settings cannot alter the immutable active-session policy. Sensitive or
  destructive rows remain unavailable unless backed by an explicit confirmation
  flow.
- Strict review retains the exact finite end time, one-time recovery workflow,
  acknowledgements, random phrase gate, and automatic focus cleanup on cancel.

## UX implications

- Timer, Cycles, and Focus Active share one stationary background and stable ring
  center. Mode changes update only the content that actually changes.
- Settings is a centered modal with top tabs; the shell behind it neither moves
  nor scrolls. Modal focus enters on open, cycles inside, closes safely with
  Escape/outside click, and returns to the Settings button.
- Every important control keeps at least a 40×40 target, visible keyboard focus,
  named non-color state, and reduced-motion behavior.

## Recovery implications

- Closing Settings discards no active session and needs no service recovery.
- Canceling strict review clears the prepared review state through the existing
  command and restores shell input/focus after the exit transition.
- Installer/uninstaller validation must use the documented rollback path and
  must not weaken service, registry, ACL, browser, or recovery protections.

## Acceptance for the first vertical slice

- No permanent sidebar or custom/macOS-like caption controls are rendered.
- One global background remains mounted while the focus state or modal changes.
- Settings opens centered with a header, close control, six top tabs, internal
  scroll, keyboard navigation, focus trapping, Escape close, and focus return.
- Existing theme, session-end, startup, health, and authority settings remain
  available; unavailable future actions are clearly disabled rather than faked.
- Global/profile/default theme resolution and reduced-motion state have unit
  coverage, and new XAML contains no literal colors.
- Release build, full tests, and a real Windows screenshot pass before moving to
  the Timer/Cycles/Focus Active composition slice.
