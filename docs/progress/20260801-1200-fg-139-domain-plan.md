# FG-139 — domain and specification plan

## Objective

Add the first Pomodoro vertical slice without changing enforcement, IPC,
persistence, or privileged machine state.

## Acceptance criteria

1. Immutable configuration, phase, and plan records exist in `FocusGuard.Domain`.
2. Configuration validation enforces the product ranges and mutually exclusive
   termination arguments.
3. Cycle-count plans end after the final focus phase and never append a final
   break.
4. Total-duration plans end at the exact requested UTC instant and identify a
   partial final phase.
5. Generated plans never contain more than 24 complete focus cycles.
6. Automated domain tests cover classic, long-break, truncation, invalid input,
   and UTC validation behavior.

## Security, UX, and recovery implications

- Security: this slice only creates data; it cannot relax a policy or terminate
  a session. The eventual service must authenticate and integrity-protect the
  serialized plan before applying break exceptions.
- UX: previews can show every phase and an exact end time, including a clear
  partial-phase warning.
- Recovery: the plan is deterministic from persisted UTC boundaries, but restart
  reconciliation is intentionally deferred to FG-142.

## Implementation order

1. Add domain enums and immutable records.
2. Add validation and deterministic phase generation.
3. Add domain tests.
4. Update the product specs and ADR.
5. Run format, build, tests, and refresh graphify.
