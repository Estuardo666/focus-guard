# FG-130 ProcessAgent checkpoint

## Summary

The active 500 ms scanner now enumerates process IDs without constructing a
managed `Process` object for every system process, reuses the 32K path buffer,
and compiles application rules once per immutable session policy. Process
deduplication state is pruned when a process exits or policy disappears.
Repeated heartbeat delivery no longer resets an unchanged policy, and
production heartbeat console output was removed.

## Files changed

- Windows process ID source and path inspector
- process enforcement worker and ProcessAgent host
- simulated monitor and its tests
- cross-process resource measurement script

## Tests added

- current PID enumeration without duplicates
- exited-process deduplication cleanup
- 10,000-rule steady-state allocation ceiling
- existing allow precedence, protected-process, grace, hash-cache, and latency
  coverage retained

## Commands executed and results

- Solution Release build: passed, zero warnings/errors
- Monitoring tests: 12/12 passed
- Windows infrastructure tests: 15/15 passed
- Desktop tests: 79/79 passed
- resource script: executed against the currently installed legacy build;
  service passed its budget and the script correctly detected two Desktops

## UX implications

No visible UI, rule result, grace period, or detection interval changed.

## Security implications

Process handles retain limited-query access. Inaccessible or disappearing
processes continue to fail open, allow rules retain precedence, and protected
process exclusions are unchanged.

## Recovery implications

Policy loss clears cached matching and deduplication state. Reconnection must
still carry the exact policy ID/hash and confirmation before enforcement resumes.

## Limitations

Installed after-measurement requires publishing/installing the new build. No
registered process or service was replaced in this checkpoint.
