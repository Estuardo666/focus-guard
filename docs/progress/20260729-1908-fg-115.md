# FG-115 — Strict confirmation modal and two-word focus phrase

## 1. Summary

- Replaced the lower inline strict-review card with a centered in-window modal
  matching the supplied mockup.
- Added a dimmed scrim, 7 px background blur, 180 ms fade-in/fade-out, and an
  8 px ease-out panel translation.
- Added reviewed English adjective/noun dictionaries and cryptographic random
  selection for an exact two-word confirmation phrase.
- Added explicit Cancel and Escape handling. Both clear the pending recovery
  credential, visible code, phrase, typed input, and acknowledgements without
  activating a session.
- Added recovery-code copy, keyboard focus entry/return, cyclic modal Tab
  navigation, and disabled background interaction while the modal is present.
- Updated `SPEC.md` and `UX_SPEC.md` so the written requirements match the
  owner-requested modal and phrase gate.

## 3. Tests added

- Deterministic generation combines exactly one word from each reviewed
  dictionary and always yields two space-separated words.
- Strict review displays the generated phrase and activation requires its exact
  ordinal match.
- Cancel clears every one-time gate and does not call the service.
- The standalone strict review uses the same two-word generator.
- Main-window markup keeps the modal outside the application shell, includes
  blur/opacity transitions, and contains no inline review card.
- Localization catalogs remain key-complete and include the English word lists
  under Spanish culture.

## 6. UX implications

- Strict review no longer expands the Focus screen or pushes content downward.
- The safety hierarchy matches the supplied redesign: exact end time, amber
  one-time-code warning, code block, readiness acknowledgements, consequence,
  two-word phrase, and explicit actions.
- The modal remains scrollable at the minimum supported height.
- Background controls cannot receive pointer or keyboard interaction while the
  review is open; Tab cycles inside the modal and Escape safely cancels.

## 7. Security implications

- The two-word phrase is explicitly a deliberate-action gate, not authentication.
  It does not replace the high-entropy recovery credential or either
  acknowledgement.
- Phrase indices use `RandomNumberGenerator.GetInt32`.
- Pending recovery material is cleared before the fade-out restores background
  interaction.
- Service-owned finite expiration, recovery hash handling, delayed elevated
  recovery, and enforcement policy are unchanged.

## 8. Limitations

- The change is build- and UI-verified from the repository but is not installed
  over the existing machine installation.
- The modal transition is intentionally short and non-bouncy; the operating
  system/platform API used by the current Avalonia version does not expose a
  cross-platform reduced-motion switch to this view.
- Store-signed Chrome/Edge publication remains the unrelated external blocker in
  FG-113.
