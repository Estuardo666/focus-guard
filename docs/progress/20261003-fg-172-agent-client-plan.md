# FG-172 — Phase 3B: agent connection and confirmation lifetime

Investigate root cause: Program hardcodes production pipe, lacks connected I/O deadline, does not clear receiver on connect failure/EOF/invalid response, ignores correlation/service readiness and receives a new server GUID on every beat. Receiver retains confirmation until policy expiry. Service listener must supply a stable instance ID for its lifetime.

Extract the actual production loop into testable agent transport/connection components. Bound one exchange including connect/read/write to 2 seconds; retain 500ms reconnect interval. Default endpoint from ProcessAgentProtocol.PipeName. Agent receiver uses a 3-second monotonic confirmation lease (opt-in constructor, existing non-agent receiver behavior unchanged), so even a stalled actor cannot enforce past freshness. On failed exchange/invalid reply/caller shutdown clear local confirmation and held ack; require fresh policy/ack handshake. Validate correlation, readiness, integrity, expiry and changed service instance. A restarted service begins a fresh confirmation exchange, never silently reuses old proof. No stop/recovery commands sent.

Scope: client runtime + service-instance field, opt-in receiver freshness, bounded session-bound audit queue and lifecycle verification. Preserve actual controller, protected exclusions, finite expiration, independent browser channel and authoritative service. Test real isolated pipes, EOF/malformed/partial/blocking peers, correlation/readiness, stable/change instance, monotonic lease, audit attribution, reconnect and shutdown. Existing startup/supervisor tests plus isolated lifecycle proof; package 0.1.22 and sync owned paths.

Full goal also includes Phase 4: peer identity/role/owner design, native verification and ACL enforcement for all endpoints/clients, bounded failures and legitimate/unauthorized compatibility tests. Remains active after this checkpoint until those gates are verified. No new host/UI, no installation, no privilege escalation.
