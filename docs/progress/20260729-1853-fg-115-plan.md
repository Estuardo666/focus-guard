# FG-115 — Strict confirmation modal and two-word focus phrase

## Status

`DONE`

## Relevant specifications

- `SPEC.md`: strict mode remains explicitly enabled and finite; activation must
  show the exact end time, one-time recovery code, recovery instructions, and
  unsaved-work warning.
- `UX_SPEC.md`: consequences, recovery, and the exact expiration remain visible;
  destructive or locking actions use explicit copy and accessible controls.
- `THREAT_MODEL.md`: the confirmation is friction against casual activation, not
  an authentication secret; service-owned expiration and elevated recovery are
  unchanged.

The owner's current request supersedes the older dedicated-screen and fixed
sentence details. This checkpoint updates those written requirements in the same
vertical slice.

## Design direction

- **Palette:** retain FocusGuard's semantic graphite surfaces, white/gray text,
  blue protection accent, and amber recovery warning.
- **Type:** retain Segoe UI Variable for interface text and Consolas for the
  recovery code.
- **Layout:** center one 840 px review panel over the existing Focus screen; use a
  shield-led header, warning strip, recovery block, two readiness rows, exact
  phrase gate, and right-aligned Cancel/Activate actions.
- **Signature:** the one-time recovery code remains the visual anchor, with the
  random two-word phrase as a compact final deliberate-action gate.
- **Motion:** fade the scrim and panel over 180 ms, translate the panel by 8 px,
  and animate background blur between 0 and 7 px using ease-out timing.

This follows the supplied mockup rather than introducing a generic dialog style.
The modal is deliberately dense because every item is a safety gate, but it stays
scrollable at the minimum supported window height.

## Plan

1. Add a focused English word dictionary and generator that returns exactly two
   words using cryptographic random indices.
2. Generate a new phrase only when opening a strict review and require an exact
   ordinal match before activation.
3. Add an explicit cancel command that clears the recovery credential, displayed
   code, acknowledgements, and typed phrase.
4. Replace the lower inline card with a centered overlay modal matching the
   supplied redesign, including blur, fade-in/fade-out, keyboard focus, Escape,
   and recovery-code copy.
5. Update English/Spanish resources and both strict confirmation view models so
   no stale fixed-sentence flow remains.
6. Update specifications, tests, task status, and checkpoint documentation.
7. Run formatting, release build, focused/full tests, and `graphify update .`.

## Acceptance criteria

- Starting strict mode opens a centered modal and no review card expands below
  the Focus content.
- The underlying app is blurred, dimmed, and non-interactive while the modal is
  open.
- Opening and closing use short fade transitions; Escape and Cancel safely clear
  all one-time review state.
- Every generated confirmation contains exactly two English focus/calm words.
- Activation stays disabled until both acknowledgements and an exact phrase match
  are present.
- The recovery code is shown once, can be copied explicitly, and is cleared on
  cancel or accepted activation.
- Formatting, build, tests, and graph update pass.

## Security implications

- The shorter phrase is not treated as authentication. It remains only a
  deliberate-action gate alongside two explicit acknowledgements and exact
  expiration/recovery disclosure.
- Random phrase generation does not affect or replace the high-entropy recovery
  credential.
- Cancel and fade-out must clear the pending credential and displayed code before
  restoring interaction to the underlying app.

## UX implications

- The review no longer shifts the main Focus layout or requires scrolling to a
  lower section.
- The modal preserves visible strict-mode consequences in every theme and offers
  keyboard-accessible Cancel, copy, confirmation, and activation controls.
- The confirmation burden becomes two memorable English words related to focus,
  calm, breathing, balance, and reduced anxiety.

## Recovery implications

- Recovery code generation, one-time display, salted credential handoff, 15-minute
  elevated recovery delay, and finite automatic expiration are unchanged.
- Dismissing the modal activates nothing and discards the pending recovery
  credential.
