## UX implications

Activity now presents locally persisted, sanitized application and website
events. Desktop launches at user logon, and after reboot accurately shows the
recovered finite session as degraded until fresh acknowledgements arrive. No
screen claims partial enforcement during agent/extension loss.

## Security implications

The service remains LocalService. Process enforcement stays in a per-user agent;
the local pipe denies Network SID and permits bounded validated messages from
authenticated local users. Application audit crosses the pipe as executable
basename plus a small outcome enum only. Website queries/fragments and executable
paths/arguments are not persisted. Exact policy ID/hash and freshness remain
required before either blocking channel operates.

The navigation hot path caches only a hash already verified by the extension's
confirmed-policy lifecycle; a changed policy hash is reverified before use.

## Recovery implications

Reboot, service replacement during an active session, agent loss, injected
installer failure, and expiration were exercised. The installer stops only the
exact installed Desktop/ProcessAgent, cryptographically verifies a restored tree,
restores service state, and relaunches a previously running ProcessAgent. Strict
expiration removed the active snapshot without Desktop intervention.

## Limitations

- Polling still permits a brief process launch window.
- Unpacked Chrome/Edge extension deployment remains a user/browser packaging
  concern; the same MV3 implementation and browser-neutral tests cover both, but
  this checkpoint's real navigation evidence was Chrome.
- FocusGuard remains intentionally defeatable by a determined administrator,
  Safe Mode, offline editing, another OS, or source modification.
