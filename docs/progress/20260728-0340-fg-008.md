# FG-008 checkpoint

## Summary

Added a mock application-rule profile editor backed by the domain validation factory, with accessible inputs, validation feedback, empty state, and removable draft rows.

## Acceptance evidence

- Supports block/allow actions and exact path, folder, file-name, and SHA-256 match modes.
- Empty or invalid values show validation feedback and do not add a rule.
- Valid values are normalized by `ApplicationRule.Create` before entering the draft list.
- Rule rows expose a remove action with an automation name.
- Release build completed with zero warnings/errors.
- Domain tests: 18/18 passed. Desktop tests: 7/7 passed.

## UX implications

The editor makes match mode explicit and keeps the draft scope visible. The empty state explains what can be added, while feedback states that changes apply only to future sessions.

## Security and recovery implications

No filesystem, process, hash computation, enforcement, persistence, or privileged operation occurs. The editor only stores in-memory draft rules.

## Limitations and next task

The profile draft is not persisted or connected to a service. Next: FG-009 website-rule editor with normalization feedback.
