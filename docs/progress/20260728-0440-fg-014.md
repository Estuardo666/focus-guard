# FG-014 checkpoint

## Summary

Added a pure `FocusGuard.Monitoring` project with fake process snapshots and a simulated monitor that proposes, but never performs, graceful-close and termination actions.

## Acceptance evidence

- Immutable application policies are matched against supplied path/hash snapshots.
- Allow rules take precedence over blocks.
- Protected snapshots are excluded.
- First match requests graceful close; termination is proposed only after an injected grace period.
- Actions are deduplicated by process instance ID and carry sanitized reasons without executable paths.
- Expired/not-yet-active policies produce no action.
- Release build completed with zero warnings/errors.
- Domain tests: 18/18; contract tests: 5/5; desktop tests: 13/13; service tests: 5/5; storage tests: 4/4; monitoring tests: 5/5.

## Security implications

No process enumeration, path resolution, process handle, close, termination, injection, or platform API is used. This is a fake-snapshot proposal engine only and cannot block a real process.

## UX implications

The action model exposes a future enforcement-health/event shape while keeping the safety boundary explicit; no UI claims real process blocking.

## Limitations and next task

Real process sources, protected-process catalog maintenance, event persistence, and action sinks remain owner-present or later work. Next: FG-015 TypeScript browser rule engine and tests.
