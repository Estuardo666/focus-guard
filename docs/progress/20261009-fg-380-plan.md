# FG-380 — plan: navegación accesible en ancho medio

## Reproducción
En el Host instalado 0.1.130, 1024×700 conserva el aviso de revisión vencida sin recorte horizontal. A 800×600 el menú de rail se reduce a 154 px y la barra vertical del rail tapa el final de «Programación». A 720×480 ya aparece el selector nativo de secciones y el aviso se mantiene legible. El candidato .131 mostró que colapsar el rail a 800×600 sin mover el corte `min-width:721px` de su alto sticky `100vh` deja el encabezado en una pantalla vacía y desplaza el contenido debajo del viewport.

## Plan
- Mover el breakpoint del selector nativo de 720 px a 1000 px, coincidiendo con el breakpoint que estrecha el rail.
- Aplicar el mismo límite al espacio superior del skip link para que no cubra el encabezado cuando el selector se mueva arriba.
- Mover el alto sticky `height:100vh` del rail de `min-width:721px` a `min-width:1001px`, de modo que el header compacto tenga solo su altura natural y el contenido siga visible.
- Actualizar `verify-dist.mjs` para validar que la regla llega al CSS de producción.
- Ejecutar pruebas UI y build del frontend; generar el Setup standalone 0.1.132 fuera del proyecto en D y validar sus hashes/manifiesto.
- Instalar el candidato autorizado y repetir la aceptación visual/UIA a 800×600; comprobar también 1024×700 y 720×480. Restaurar la ventana a 1216×799.

## Riesgos y límites
Solo cambia la presentación de la navegación en ventanas de hasta 1000 px. Mantiene las mismas siete secciones, etiquetas localizadas, permisos, comandos IPC y foco/teclado. No cambia reglas, perfiles, sesión ni preferencias guardadas. Si el selector estrecho no cabe a 520 px, el layout de dos filas existente sigue aplicando.
