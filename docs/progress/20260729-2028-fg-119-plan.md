# FG-119 — Desktop startup crash after FG-118

## Symptom

After reinstalling the FG-118 package, the Windows service and process agent
run, but `FocusGuard.Desktop.exe` exits before showing its main window.

## Root cause evidence

- Executing the installed Desktop reproduces the failure deterministically:
  it exits within five seconds with code `-532462766`.
- Windows Application log event 1026 reports
  `InvalidOperationException: No animator registered for the property
  RenderTransform`.
- The stack reaches `MainWindow.axaml:14` while Avalonia attaches style
  animations.
- The only keyframe animation introduced by FG-118 animates
  `RenderTransform` on `Border.ringGlow.pulsing`.

## Root cause hypothesis

Confirmed: Avalonia 12 can interpolate the parsed transform through
`TransformOperationsTransition`, but its keyframe animation system has no
registered animator for the `RenderTransform` object property. Attaching the
halo style therefore terminates the Desktop during XAML initialization.

## Implementation plan

1. Add a regression contract that rejects `RenderTransform` setters inside
   keyframe animations.
2. Keep the glow breathing through supported opacity keyframes and remove only
   the unsupported transform keyframes.
3. Build and run the Desktop from the corrected output, proving it remains
   alive and creates a window.
4. Run formatting, full tests, package checks, and `graphify update .`.
5. Rebuild and verify a replacement installer.

## Security implications

None. The change is limited to a visual animation. Service authority, strict
expiration, enforcement, IPC validation, recovery, and installer privileges
are unchanged.

## UX implications

The application opens again. The ring retains its blurred breathing glow
through gradual opacity changes; only the unsupported 3.5% geometric expansion
is removed.

## Recovery implications

No recovery behavior changes. The running service and process agent do not
need to be stopped for source-level diagnosis or testing.
