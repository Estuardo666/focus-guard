# FG-118 — Screenshot-driven Dark Zen UI corrections

## Goal

Correct the visual defects identified in the owner's nine screenshots without
changing FocusGuard behavior, enforcement, strict-session semantics, or
recovery.

## Acceptance criteria

- Sidebar entries render as free icon-and-label rows with no outer or nested
  selection rectangles and no white hover flash.
- Toggle switches and strict acknowledgements use dedicated templates without
  rectangular control backgrounds.
- The recovery-code copy glyph is centered.
- Buttons are rounded but not capsule-shaped.
- Buttons, inputs, selectors, lists, switches, and checks interpolate hover,
  pressed, selected, and keyboard-focus states.
- The timer has a visible layered halo; the active halo breathes on a calm
  5.6-second cycle.
- Profile title, rule-count subtitle, and profile swatches share an explicit
  left alignment, with comfortable title padding.
- Navigating among Focus, Profiles, Activity, and Settings animates the
  incoming screen with a short, interruptible fade and lift.
- Automated design-contract tests cover the regressions.
- Formatting, Release build, relevant tests, graph update, and installer
  packaging pass.

## Implementation plan

1. Remove template-part hover painting from generic buttons and move state
   changes to control-level properties.
2. Replace the Fluent toggle and check visuals used by the main window with
   focused FocusGuard templates.
3. Refine shared radii, alignment, transitions, and focus feedback.
4. Replace the ineffective shadow-only ring halo with a rendered blurred ring
   and breathing opacity/scale animation.
5. Align and pad the profile header and add screen-entry transitions.
6. Extend source-level XAML tests, validate, update the graph, and rebuild the
   installer.

## UX implications

These changes remove accidental nested rectangles and flashing, make every
interactive state feel continuous, improve header scanning, and make the
running timer feel calm and alive. Keyboard focus remains explicit and the
strict warnings remain unchanged.

## Security implications

Visual templates and transitions only. No policy, service, IPC, storage,
browser, recovery, session expiration, or privileged behavior changes.

## Recovery implications

The recovery-code value, acknowledgement requirements, copy action, delayed
recovery path, and exact strict expiration remain unchanged. Only their visual
presentation is corrected.
