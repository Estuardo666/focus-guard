# FG-015 checkpoint

## Summary

Added a dependency-free TypeScript browser rule engine and Node test suite for local URL evaluation.

## Acceptance evidence

- Normalizes bare domains, subdomains, path wildcards, and scheme wildcards.
- Removes query strings/fragments from URL matching and sanitized log values.
- Explicit allow rules override matching blocks; unmatched URLs default to allow.
- Browser-internal pages fail open.
- Malformed URLs and query-bearing rule patterns are handled safely.
- Compiled rules can be reused for repeated evaluations.
- `npm test` passes 6/6 with no test failures or warnings.
- Full .NET restore/build/test remains green: 50/50 tests, 0 build warnings/errors.

## Security and privacy implications

The engine evaluates only the URL supplied to the local browser event, strips query/fragment data, never sends browsing history, and performs no extension installation or browser-policy changes.

## UX implications

The rule behavior matches the desktop editor and domain matcher, preserving allow precedence and fail-open behavior across layers.

## Limitations and next task

Manifest V3 packaging, native messaging, extension heartbeat, and browser integration remain deferred. Next: FG-016 CI, formatting, coverage, and report automation.
