# FG-143 checkpoint — Desktop and tray phase status slice

## Summary

Added phase-aware Desktop and tray presentation backed by the authoritative IPC
status. Normal breaks expose `Continue focus now`; strict sessions and focus
phases do not.

## Files changed

- `FocusViewModel` phase state, localized labels, and `SkipBreak` command.
- Main window active-session card and tray flyout phase panels.
- Spanish and English resources.
- ViewModel phase-status regression test.

## Tests added

- Active cycle status renders phase, cycle, next transition, and skip eligibility.

## Commands executed

- Targeted `dotnet format` for Desktop and Desktop tests.
- `dotnet build --no-restore`.
- `dotnet test tests/FocusGuard.Desktop.Tests/FocusGuard.Desktop.Tests.csproj --no-build --no-restore --filter FullyQualifiedName~FocusViewModelTests`.
- Full suite and `graphify update .` are run after this checkpoint.

## Results

Desktop build succeeds with zero warnings/errors; the focused ViewModel suite
passes 41 tests. The full .NET suite passes 300 tests, and targeted format
verification passes for the modified Desktop code and test file.

## UX implications

Phase names are readable text, and the skip action is absent unless the service
reports an authorized normal break. The tray and main window share the same
state, avoiding conflicting countdowns.

## Security implications

The command sends only the phase index reported by the service. Strict mode is
not made weaker by a hidden or disabled equivalent action.

## Limitations

FG-143 still needs the inactive cycle-mode selector, preset/custom editor,
break-exception editor, and strict preparation review. Those remain in the
next FG-143 slice.
