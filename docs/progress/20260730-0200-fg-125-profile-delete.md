# FG-125 Profile Delete

## 1. Summary

Added persistent profile deletion with a two-step, in-window confirmation. The
confirmation identifies the selected profile, shows how many application and
website rules will be removed, and states that deletion cannot be undone.

FocusGuard refuses to delete the final remaining profile and selects a remaining
profile after successful deletion.

## 6. UX implications

Profiles now has a danger-styled Delete action. It never deletes immediately:
the user first sees an explicit warning with the profile name and rule counts,
then chooses either Keep profile or Delete profile permanently.

The confirmation closes if the selected profile changes or a session becomes
active. After deletion, another saved profile is selected automatically.

## 7. Security implications

Deletion is unavailable during active sessions and busy operations. It changes
saved future-session configuration only; the authoritative active policy is
unchanged.

## 8. Limitations

- Deletion is permanent; this checkpoint does not add a recycle bin or undo.
- The last-profile protection is enforced in the Desktop workflow. The lower
  storage API remains a general-purpose primitive and can delete any explicitly
  requested profile.
- Compiled XAML and automated tests validate the UI contract; no screenshot
  review was performed.
