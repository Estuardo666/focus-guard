# FG-140 — persistent presets and break exceptions

## 1. Summary

Added SQLite schema version 3 for Pomodoro presets and per-profile break
exceptions. Existing profile databases are upgraded additively. Three stable
built-in presets are seeded and protected from deletion; custom presets support
round-trip persistence and deletion. Break application and website rules are
stored separately from normal profile rules and accept only `Allow` actions.

## 5. UX implications

The persistence layer now supports immutable built-in cards, duplicated custom
presets, profile defaults, and a separate list of items available during
authorized breaks. No Desktop controls are exposed yet; that is FG-143.

## 6. Security implications

Break exceptions cannot overwrite or weaken normal profile rules and storage
rejects `Block` actions for the break tables. Built-in presets cannot be
deleted. The data is not yet part of an active signed enforcement policy;
FG-142 must include it in integrity coverage before exceptions are applied.

## 7. Limitations

The store does not yet prepare or activate sessions, sign plans, authorize
phase transitions, or reconcile restart state. Schema seed names are currently
stored as stable product strings; localization of user-facing UI is FG-144.

## 8. Next task

FG-141: add versioned IPC preparation/activation, phase status, idempotent
transitions, and normal-mode `SkipBreak` behavior in the authoritative service.
