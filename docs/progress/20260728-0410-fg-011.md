# FG-011 checkpoint

## Summary

Added a standalone `FocusGuard.Contracts` project containing versioned IPC envelopes, typed status/activation messages, bounded JSON validation, and codec helpers.

## Acceptance evidence

- Protocol version and message type are closed and validated.
- Correlation IDs are required and payloads are bounded to 64 KiB with a maximum JSON depth of 16.
- Payloads must be JSON objects with comments/trailing commas disallowed.
- Activation requests enforce one-minute to 30-day durations, valid profile IDs, recovery-delay bounds, and normal-mode zero delay.
- Typed activation requests round-trip through the versioned envelope.
- Release build completed with zero warnings/errors.
- Contract tests: 5/5 passed; domain tests: 18/18; desktop tests: 13/13.

## Security implications

The contract layer performs no transport or system action. It avoids polymorphic CLR deserialization and rejects malformed or oversized messages before a future named-pipe implementation can process them.

## UX and recovery implications

None directly; this milestone only defines service/UI message boundaries. Recovery-code data is not represented in the contracts.

## Limitations and next task

Named-pipe transport, authentication/ACLs, timeouts, and service acknowledgements remain deferred. Next: FG-012 in-memory service simulator.
