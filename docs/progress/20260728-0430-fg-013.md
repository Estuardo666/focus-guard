# FG-013 checkpoint

## Summary

Added a `FocusGuard.Storage` project with a real SQLite profile/rule schema and parameterized transactional persistence, plus temporary-directory integration tests.

## Acceptance evidence

- Profiles, application rules, and website rules persist with foreign keys and cascade relationships.
- Save operations replace a profile's rule set in one transaction.
- Values containing quotes round-trip without SQL interpolation.
- Data persists across store instances and missing profiles return null.
- Async operations accept cancellation tokens; canceled initialization is tested.
- Connection pooling is disabled so temporary database disposal is deterministic.
- Restore succeeded with no vulnerable packages reported by `dotnet list ... package --vulnerable --include-transitive`.
- Release build completed with zero warnings/errors.
- Domain tests: 18/18; contract tests: 5/5; desktop tests: 13/13; service tests: 5/5; storage tests: 4/4.

## Security implications

SQL commands are parameterized and schema relationships use foreign keys. The dependency path uses `Microsoft.Data.Sqlite 10.0.0` with `SQLitePCLRaw.lib.e_sqlite3 2.1.12`; the vulnerability audit reported no vulnerable packages.

## UX implications

None directly; this is storage infrastructure for future profile editing and service state.

## Limitations and next task

Schema migration beyond version 1, encrypted secrets, machine/user data locations, and policy snapshot integrity remain future work. Next: FG-014 process-monitor simulation with fake process snapshots.
