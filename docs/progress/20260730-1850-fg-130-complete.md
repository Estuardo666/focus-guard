# FG-130 completion checkpoint

## Summary

FG-130 is complete. FocusGuard now prevents duplicate Desktop processes,
reduces hidden-inactive Desktop polling by 80%, avoids full visual-tree
renotification for unchanged status, and removes the largest allocation sources
from active process scanning. Visible and active behavior, immutable policy,
protected-process exclusions, IPC, expiration, and recovery remain unchanged.

The installed legacy build currently uses 569.02 MB working set across five
processes; 419.95 MB of that is two hidden Desktop instances. After deployment,
the second Desktop launch will signal and restore the first process rather than
retaining another approximately 200 MB instance.

## Files changed

- Desktop single-instance lifecycle, adaptive refresh, and differential status
  presentation
- Windows PID enumeration, pooled path inspection, compiled rule matching, and
  ProcessAgent heartbeat handling
- resource measurement script, automated tests, task log, and Graphify outputs

Existing FG-127 through FG-129 typography, timer, icon, and installer changes
were preserved.

## Tests added

- per-user/session second-instance activation
- adaptive refresh intervals
- unchanged and countdown-only property notification sets
- current Windows PID enumeration
- process deduplication cleanup
- bounded allocations with 10,000 compiled application rules

## UX implications

Opening FocusGuard twice now restores the existing window. The visible and
active refresh interval stays at one second. Hidden active sessions retain
timer, block, and session-end behavior; only hidden inactive polling moves to
five seconds. Visible motion and all existing styling remain intact.

## Security implications

The fixed activation event is isolated by Windows session and user identity.
Process inspection continues to use limited-information handles and fail open.
Allow precedence, protected exclusions, exact policy confirmation, and
sanitized audit behavior are unchanged.

## Recovery implications

Service-owned strict persistence, monotonic expiration, recovery delay, and
automatic release are unchanged. Policy loss clears only derived matcher and
deduplication caches; enforcement still requires a fresh confirmed policy.

## Limitations

- The installed legacy binaries were not replaced, so its two already-running
  Desktop instances remain until the next authorized install/restart.
- The original tray bitmap was retained to guarantee pixel-identical UI; no
  image-memory claim is included in the measured improvement.
- Native browser hosts remain one process per browser-owned native port.
