# FG-130 implementation plan

## Goal and acceptance criteria

Reduce FocusGuard background CPU, memory, and allocation pressure without
changing visible UI, session semantics, enforcement policy, protected-process
rules, IPC contracts, persistence, expiration, or recovery behavior.

1. Prevent more than one Desktop instance per signed-in Windows session and
   restore the existing window when FocusGuard is launched again.
2. Keep one-second status refresh while visible or active, use a five-second
   refresh only while hidden and inactive, and refresh immediately on restore.
3. Notify Avalonia bindings and commands only when their source state changes.
4. Replace allocation-heavy process enumeration and path inspection with pooled
   Windows buffers, while preserving fail-open handling of inaccessible or
   disappearing processes.
5. Compile application-rule lookup once per active policy and release stale
   process-deduplication state.
6. Remove production heartbeat console chatter without removing sanitized
   audit events or failure logs.
7. Prove the changes with automated behavior, allocation, and resource canaries.

The existing service budgets remain release gates: idle CPU below 1%, idle
working set below 100 MB, and median process detection below one second.

## Baseline

A ten-second local observation found two hidden installed Desktop instances at
203.91 MB and 219.64 MB working set, two browser-owned native hosts at 36.42 MB
and 44.49 MB, and the service at 68.01 MB. Normalized idle CPU was 0.03% and
0.01% for Desktop and effectively zero for the native hosts and service.

The installed ProcessAgent was not running during this observation, so active
scan improvement will be measured with a deterministic in-process allocation
canary and the existing owner-present test-target latency path rather than by
activating a real policy merely to profile it.

## Security, UX, and recovery implications

- Security: the single-instance signal is local to the current Windows session
  and user identity and accepts only the fixed `show` action. Process inspection
  retains limited-information handles, protected exclusions, and fail-open
  handling. No new privileged channel or mutable policy input is introduced.
- UX: launching FocusGuard again restores the existing window. Visible and
  active refresh cadence remains one second, and the active timer and halo keep
  their current appearance. A restored hidden window refreshes before display.
- Recovery: service-owned expiration and strict reconciliation remain
  unchanged. Hidden active sessions keep the existing one-second status loop
  and five-second activity polling, so session-end and block notifications are
  not deferred.

## Delivery checkpoints

1. Desktop lifecycle, differential status presentation, tests, and local
   resource canary.
2. Process enumeration, compiled matching, bounded deduplication state, tests,
   and allocation/latency canaries.
3. Full formatting, Release build, all tests, Graphify refresh, task closure,
   and a completion report.

Existing uncommitted FG-127 through FG-129 typography and timer work is
owner-owned and must be preserved.
