# FG-006 checkpoint

## Summary

Connected the inactive Focus screen to a safe mock view model with duration presets, strict-mode explanation, and an explicit simulator-only start action.

## Acceptance evidence

- Profile name and rule counts are data-bound rather than duplicated in the view.
- Duration selection exposes 25-, 50-, and 90-minute presets.
- Strict mode is opt-in and explains that review/recovery acknowledgement is required.
- Start action only updates a local status message and explicitly says no session was activated.
- Typed compiled bindings are used for the window and duration items.
- Release build completed with zero warnings/errors.
- Domain tests: 18/18 passed. Desktop view-model tests: 2/2 passed.

## UX implications

The inactive state now gives the user a clear setup path while keeping consequences visible. The simulator disclosure prevents the screen from claiming that real blocking is active.

## Security and recovery implications

No service, process, browser, persistence, or enforcement behavior is invoked. Strict mode remains a UI-only flag and cannot create persistence or lockout.
