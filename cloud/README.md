La topología de staging usa Keycloak y API en Cloud Run, PostgreSQL en Neon y portal/BFF en Vercel. Fases 1 y 2 están aceptadas para identidad, membresía de dispositivos y transferencia manual E2EE. Fase 3 ya integra en Windows la sincronización automática opt-in de tema, idioma y duración predeterminada, con outbox DPAPI, recuperación, conflictos y reset explícito. Sigue pendiente su aceptación automática física entre dos PCs. La cuenta cloud es opcional y no habilita bloqueo remoto.

## Controles de seguridad implementados

- Keycloak 26.8.0 está fijado a una imagen oficial por digest, usa Neon con TLS y conserva realm/sesiones entre reinicios. Clientes nativo y BFF están separados; flujos de contraseña directa e implicit deshabilitados; tokens duran cinco minutos, refresh rota, y el lockout por intentos está habilitado.
- La plantilla versionada mantiene `registrationAllowed=false` como valor seguro por defecto. En el realm de staging, SMTP Resend ya se conectó y se probó; el registro/verificación/reset público se validó en Fase 1. Keycloak requiere correo verificado, ofrece TOTP opcional y aplica contraseñas de al menos 15 caracteres.
- La API valida firma RS256, issuer, audiencia `focusguard-api` y expiración. Para devolver estado o aceptar bootstrap comprueba además el correo y la sesión vigente con `userinfo` de Keycloak. El endpoint de cuenta sólo identifica si existe una membresía para la cuenta; no demuestra que esta instalación pertenezca a ella ni concede autoridad de bloqueo.
- El portal usa authorization code + PKCE, `state`/`nonce`, cookie opaca `__Host-` Secure/HttpOnly/SameSite, tokens cifrados AES-GCM en PostgreSQL, CSRF en logout y revocación remota. React sólo recibe el estado de cuenta sanitizado.
- Host/React ofrece inicio/cierre nativos, estado sanitizado, seguridad de cuenta, bootstrap del primer PC, pairing manual por huella, transferencia de un solo uso y sincronización automática opt-in. Tema, idioma y duración se guardan como documento XChaCha/Ed25519 con CAS; el Host restaura consentimiento/checkpoint DPAPI y reanuda el loop, resuelve conflictos y conserva límites de backoff/Retry-After. Reglas de apps/sitios, perfiles, permisos, agenda e historial permanecen locales; React nunca recibe los valores del documento.
- `mobile/android` agrega cliente OIDC nativo, identidad Android Keystore/libsodium, verificación de membresía y recepción del sobre firmado. La prueba aceptada confirmó el teléfono enlazado y membresía verificada; el bloqueo Android todavía no está implementado.
- No existe Zero Data Retention global: Neon persiste identidad y sesiones cifradas; Keycloak persiste usuarios/sesiones; Vercel y Resend procesan datos operativos según sus servicios. No se suben historial, reflexiones ni claves E2EE.
